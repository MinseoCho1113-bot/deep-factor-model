# Deep Factor Model: Autoencoder Asset Pricing vs. Linear Factor Models

A research project in R comparing **nonlinear latent factor
extraction** (a conditional autoencoder) against **linear factor models**
(PCA / statistical factors, and observable factors à la Fama-French 5 +
Momentum) for equity risk and return modeling — plus a risk-analytics layer
that decomposes portfolio risk (VaR/CVaR) under each factor structure.

Methodologically follows the "Autoencoder Asset Pricing Models" line of work
(Gu, Kelly, Xiu 2021) and the broader empirical asset pricing + ML literature
(Gu, Kelly, Xiu 2020, "Empirical Asset Pricing via Machine Learning").

## Research Question

Do nonlinear, characteristic-conditioned latent factors extracted via a deep
autoencoder explain the cross-section and time-series of equity returns
better than:
1. Observable factors (Fama-French 5 + Momentum),
2. Linear statistical factors (PCA on the return covariance matrix),

as measured by in/out-of-sample total R², Sharpe ratio of the implied
factor-mimicking portfolios, and pricing-error (alpha) tests?

A secondary risk-analytics question: does the resulting nonlinear factor
structure change **portfolio risk decomposition** (VaR/CVaR, component/
marginal risk contribution) relative to the linear benchmark?

## Model Architecture (Conditional Autoencoder)

Following Gu-Kelly-Xiu (2021), returns are modeled as:

    r_{i,t} = beta(z_{i,t-1})' * f_t + e_{i,t}

- **Beta network**: maps firm characteristics `z_{i,t-1}` (momentum,
  volatility, size proxy, liquidity, illiquidity) to time-varying factor
  loadings `beta(z_{i,t-1})`, via a feed-forward network.
- **Factor network**: maps the cross-section of returns `r_t` to latent
  factors `f_t` via a linear encoder.
- The two networks are trained **jointly** (`torch` for R, no Python/
  reticulate dependency) to minimize reconstruction error of `r_t`, making
  this a *conditional* autoencoder rather than plain PCA.

Benchmarks:
- **PCA factors**: standard statistical factors from the return covariance
  matrix (linear, unconditional).
- **Fama-French 5 + Momentum**: observable factor benchmark, pulled live
  from Ken French's data library via the `frenchdata` package.

## Data

Academic-grade versions of this model use a firm-characteristic panel from
CRSP/Compustat (via WRDS) — the gold standard in this literature, but
paywalled. This project uses a free substitute:

- **Returns**: `tidyquant` pull of a random S&P 500 sample's daily/monthly
  adjusted-close returns.
- **Characteristics**: derived from price/volume alone — 12-1 momentum,
  60-day realized volatility, a market-cap *proxy* (price × volume, not
  true shares outstanding), 20-day dollar volume, and Amihud (2002)
  illiquidity.
- **Factor benchmarks**: Ken French Data Library, live via `frenchdata`.

**This is a real limitation, not a footnote**: no book-to-market,
profitability, investment, or accrual characteristics, because those need
balance-sheet data this project doesn't have wired up. See
[`docs/data_notes.md`](docs/data_notes.md) for the full proxy-vs-true-field
table and how to extend it with real fundamentals (SEC EDGAR / a paid API).

## Setup & Reproduction

```bash
git clone <this repo>
cd deep-factor-model
Rscript -e 'renv::restore()'   # installs exact locked package versions
Rscript -e 'torch::install_torch()'  # downloads the libtorch backend (~a few hundred MB, one-time)
Rscript run_pipeline.R
```

**Known environment gotcha (macOS)**: `tidyquant`'s dependency chain
(`forecast` → `RcppArmadillo`) needs a Fortran compiler to build from
source. If R has no `gfortran`, `renv::restore()` will fail on
`RcppArmadillo` with a linker error (`library 'emutls_w' not found`). Fix:

```bash
brew install gcc   # bundles gfortran
```

Then add to `~/.R/Makevars` (R's official installer expects gfortran at
`/opt/gfortran`, which Homebrew doesn't use, so this repoints it):

```
FC = /opt/homebrew/bin/gfortran
F77 = /opt/homebrew/bin/gfortran
FLIBS = -L/opt/homebrew/Cellar/gcc/<version>/lib/gcc/current -lgfortran -lquadmath
```

## Evaluation Metrics

- **Total R²**: fraction of realized return variation explained
  (`1 - Σ(r - r̂)² / Σr²`, the un-demeaned convention used in the ML asset
  pricing literature, not classical OLS R²).
- **Sharpe ratio** of each model's implied factor-mimicking portfolio.
- **Pricing errors**: average |alpha| across test assets (stretch goal:
  GRS-style joint test).
- **Risk decomposition**: historical VaR/CVaR and factor-implied portfolio
  variance, linear (PCA) vs. nonlinear (autoencoder) factor structure.

Current scripts report **in-sample** fit only; a genuine out-of-sample
predictive R² (rolling-window refit, no look-ahead) is the natural next
step — see the `NEXT` messages printed by `scripts/06` and `scripts/07`.

## What's Actually Been Done So Far

This repo is a working, tested scaffold — not yet a finished research
result. Concretely, as of the last commit:

1. **All 7 pipeline scripts run end to end without errors**, verified via a
   smoke test on a 15-ticker, 2018–present sample (small on purpose, for
   fast iteration). Two real bugs were caught and fixed this way:
   - `scripts/01`: `dplyr::slice_sample()` doesn't take a `seed=` argument
     in current `dplyr` — replaced with `set.seed()` before the call.
   - `scripts/04`: Ken French's data library returns the market factor
     column as `Mkt-RF` (hyphen), not `Mkt.RF` — added a `rename()` step.
2. **The `torch` autoencoder trains and its loss decreases** on the smoke
   sample (conditional autoencoder architecture in `R/autoencoder.R`,
   trained jointly per Gu-Kelly-Xiu).
3. **5 unit tests pass** for the characteristic-construction functions
   (`tests/testthat/test-characteristics.R`) — momentum look-ahead
   avoidance, non-negativity of Amihud illiquidity, rolling-mean
   correctness.
4. **Not yet done**: a full production run (200 tickers, 2000–present, 200
   training epochs — the smoke test intentionally used far smaller values
   for speed), the out-of-sample evaluation split, real fundamentals data,
   and the component-VaR decomposition using the autoencoder's
   time-varying betas (flagged as a stretch goal in `scripts/07`).
